## Description

Como **usuário mobile**, quero que o app respeite a tela do meu celular (notch, área segura, toques sem delay) **para** usar sem fricção.

> **Contexto:** o app já tem `<meta viewport>` correto e PWA manifest, mas faltam ajustes finos: `safe-area-inset` (notch iPhone), `touch-action: manipulation` (eliminar delay de double-tap), tap highlight transparente, e o popover de filtros estoura em viewport ≤360px.

## Acceptance Criteria

- [ ] **Given** estou em iPhone com notch (Safari), **when** acesso qualquer rota do `/app/*`, **then** o conteúdo principal não fica atrás da barra de status (top) nem do home indicator (bottom). O `<main>` em `AppShell.tsx` respeita `env(safe-area-inset-top)` e `env(safe-area-inset-bottom)`.
- [ ] **Given** estou em mobile, **when** dou double-tap em qualquer botão ou input, **then** **não há delay de zoom de 300ms** (eliminado por `touch-action: manipulation`).
- [ ] **Given** estou em mobile, **when** toco em qualquer botão, **then** **não aparece a "caixa azul" de tap highlight** padrão do Android/iOS (substituído por `:active` discreto via Tailwind, `active:bg-muted` ou similar).
- [ ] **Given** estou em viewport 360x640 (iPhone SE), **when** abro o popover de filtros em `/app/expenses` (`ExpenseFiltersPopover.tsx`), **then** o popover não estoura nas bordas — ocupa `calc(100vw - 2rem)` com 16px de margem segura de cada lado.
- [ ] **Given** estou em viewport ≥640px (`sm` breakpoint), **when** abro o mesmo popover, **then** ele mantém a largura original `w-80` (320px) — comportamento atual preservado.
- [ ] **Given** Sonner (toast) ou Radix toast dispara, **when** estou com teclado virtual aberto, **then** o toast aparece em `top` (não coberto pelo teclado) — config do `<Toaster position="top-center" />` em mobile.
- [ ] **Given** todas as mudanças aplicadas, **when** rodo `npm run build`, **then** **não há regressão visual em desktop** (≥1024px) — o `pb-24 md:pb-6` antigo continua funcional.

## Technical Notes

### 1. `index.css` — regras globais
- **Arquivo:** `src/index.css`
- Adicionar no final do bloco `@layer base`:
  ```css
  @layer base {
    /* Eliminar delay de double-tap zoom em elementos interativos */
    button,
    a,
    input,
    select,
    textarea,
    [role="button"] {
      touch-action: manipulation;
      -webkit-tap-highlight-color: transparent;
    }

    /* Permitir que o body respeite safe-area no scroll bounce do iOS */
    html, body {
      overscroll-behavior-y: none;
    }
  }
  ```

### 2. `AppShell.tsx` — safe-area no main
- **Arquivo:** `src/components/layout/AppShell.tsx:19`
- Substituir:
  ```tsx
  <main className="flex-1 overflow-y-auto bg-background p-4 md:p-6 pb-24 md:pb-6">
  ```
- Por:
  ```tsx
  <main
    className="flex-1 overflow-y-auto bg-background p-4 md:p-6"
    style={{
      paddingTop: 'max(1rem, env(safe-area-inset-top))',
      paddingBottom: 'max(6rem, calc(env(safe-area-inset-bottom) + 1.5rem))',
      paddingLeft: 'max(1rem, env(safe-area-inset-left))',
      paddingRight: 'max(1rem, env(safe-area-inset-right))',
    }}
  >
  ```
- **Importante:** o `pb-24` original em mobile é proposital para deixar espaço ao FAB (`FloatingActionButton`) e futura BottomNav (Story 3.5). Manter equivalência (`6rem ≈ pb-24`) + safe-area-inset-bottom.
- Em desktop (`md:`), reduzir o padding via override (Tailwind `md:p-6` ainda funciona, mas o style inline tem precedência) — alternativa mais limpa: usar Tailwind arbitrary `pt-[max(1rem,env(safe-area-inset-top))]`. **Preferir Tailwind se possível** para manter coerência. Se não funcionar (alguns valores `env()` podem ter quirks), usar `style` inline.

### 3. `ExpenseFiltersPopover.tsx` — largura responsiva
- **Arquivo:** `src/components/expenses/ExpenseFiltersPopover.tsx`
- Localizar `<PopoverContent className="w-80 ...">` (provavelmente linha ~67 conforme assessment).
- Substituir por:
  ```tsx
  <PopoverContent className="w-[calc(100vw-2rem)] max-w-sm sm:w-80" align="end">
  ```
- `align="end"` ajuda a manter o popover dentro da viewport quando o trigger está perto da borda direita.

### 4. Sonner — posição no mobile
- **Arquivo:** `src/App.tsx`
- Localizar `<Sonner />` (importado como `Toaster as Sonner`).
- Substituir por:
  ```tsx

  ```
- `position="top-center"` evita conflito com teclado virtual no mobile.
- Manter o `<Toaster />` (Radix) também — vários componentes do projeto já usam.

- NÃO alterar `index.html` — viewport e meta tags já estão corretos.
- NÃO modificar componentes específicos (`Dashboard`, `Expenses`, etc.) — esta story foca apenas em foundation global.
