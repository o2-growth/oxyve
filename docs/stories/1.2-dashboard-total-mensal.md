# Story 1.2: Dashboard com total consolidado mensal

## Status: Approved

## Description

Como **admin / gestor / funcionário**, quero ver o total gasto no mês corrente (e comparativo com o mês anterior) **independente** do relatório atual, **para** acompanhar o consumo financeiro real ao longo do tempo.

> **Contexto:** o `Dashboard.tsx` hoje só mostra "Período Atual" baseado em `currentReportExpenses` (despesas do relatório aberto). Se o funcionário não tem relatório em andamento, vê R$ 0,00 — confuso. Para o admin/gestor, falta visão consolidada da org.

## Acceptance Criteria

- [ ] **Given** sou um funcionário autenticado, **when** acesso `/app/dashboard`, **then** vejo um novo bloco "Visão Mensal" com 2 cards: "Total este mês" e "Total mês anterior", agregando apenas as MINHAS despesas (`expenses.user_id = me`) com `date` no respectivo período.
- [ ] **Given** sou manager ou admin, **when** acesso o mesmo dashboard, **then** os mesmos cards mostram o total da ORG inteira (`expenses.org_id = my_org_id`), não só meu.
- [ ] **Given** os 2 cards estão renderizados, **when** há mudança percentual entre os meses, **then** "Total este mês" exibe um indicador de variação (`▲ +15%` em verde se aumento, `▼ −10%` em vermelho se queda; cinza se variação 0 ou mês anterior == 0).
- [ ] **Given** não há despesas no mês corrente, **when** o card "Total este mês" carrega, **then** exibe `R$ 0,00` em cinza com texto secundário "Nenhuma despesa este mês" (não confundir com "loading").
- [ ] **Given** estou em mobile (viewport 390x844), **when** vejo a "Visão Mensal", **then** os cards empilham (1 coluna), o valor é ≥24px e legível, e a variação fica logo abaixo do valor.
- [ ] **Given** a query falha, **when** o erro retorna, **then** o card mostra estado de erro com botão "Tentar novamente" (não toast genérico).

## Technical Notes

### Hook novo
- **Arquivo:** `src/hooks/useMonthlyTotals.ts` (novo)
- **API sugerida:**
  ```ts
  type MonthlyTotals = {
    current_month_cents: number;
    previous_month_cents: number;
    current_month_count: number;
    previous_month_count: number;
  };
  function useMonthlyTotals(): UseQueryResult<MonthlyTotals>
  ```
- **Query:** uma única chamada que retorna os 2 meses. Prefer 2 selects paralelos via `Promise.all` (Supabase JS client) sobre `expenses` filtrando `date >= startOfMonth` e `date < startOfNextMonth`.
- **Scope:** **NÃO** é necessário filtrar manualmente por `user_id`/`org_id` — RLS da tabela `expenses` já garante:
  - `employee` só enxerga próprias despesas (RLS "Users can view own expenses").
  - `manager`/`admin` enxergam org inteira (RLS "Managers can view org expenses").
  - Logo, **um único `select sum(amount_cents)` retorna o escopo correto automaticamente.**
- **Snippet de referência (não literal):**
  ```ts
  const startCurrent = startOfMonth(today);
  const startNext = startOfMonth(addMonths(today, 1));
  const startPrev = startOfMonth(subMonths(today, 1));
  const currentQuery = supabase.from('expenses')
    .select('amount_cents', { count: 'exact' })
    .gte('date', formatISO(startCurrent, { representation: 'date' }))
    .lt('date', formatISO(startNext, { representation: 'date' }));
  // mesma coisa para o anterior
  ```
- Usar `date-fns` (já presente no projeto) para `startOfMonth`, `subMonths`, `addMonths`.

### UI no Dashboard
- **Arquivo:** `src/pages/app/Dashboard.tsx`
- **Onde inserir:** após o `<CurrentReportCard>` (linha 56-61) e ANTES do grid de 4 stats existente (linha 64). Criar uma nova seção `<section className="mb-6 md:mb-8">` com `<h2 className="text-sm font-semibold text-muted-foreground uppercase mb-3">Visão Mensal</h2>` e abaixo um grid `grid-cols-1 sm:grid-cols-2 gap-4`.
- **Componente novo:** `src/components/dashboard/MonthlyTotalsCard.tsx` (novo) que recebe `total_cents`, `count`, `comparison?: { previous_cents, percent_change }`, `isLoading`, `error`, `onRetry`.
- **Estilo:** usar `<Card>` shadcn já padrão; valor em `text-2xl md:text-3xl font-bold`. Variação em badge pequeno ao lado do valor.
- **Cores semânticas:** verde via `text-green-600 dark:text-green-500`, vermelho via `text-destructive`. Tokens Tailwind do projeto.

### Diferenciação por papel
- A diferenciação automática vem do RLS — **não duplicar lógica** no frontend. Apenas adicionar um `<CardDescription>` contextual:
  - Para `employee`: "Suas despesas do mês"
  - Para `isManager` ou `isAdmin`: "Despesas da organização"
- Detectar via `useAuth()` (já em uso no Dashboard, linha 19).

### Empty state
- Se `current_month_cents === 0 && current_month_count === 0`, renderizar `R$ 0,00` em `text-muted-foreground` + texto "Nenhuma despesa este mês".

### Estado de erro
- Card exibe ícone de alerta (`<AlertTriangle />`) + texto "Não foi possível carregar" + botão `<Button variant="outline" size="sm" onClick={refetch}>Tentar novamente</Button>`.

## Testing Requirements

### Manual
- Logar como `employee`, criar 3 despesas no mês corrente e 2 no mês anterior. Validar valores e contagem.
- Logar como `admin`, validar que o card mostra a soma da org inteira.
- Apagar despesas do mês corrente e validar empty state.

### Smoke mobile (390x844)
- Cards empilham; variação visível; tipografia ≥24px.

### Edge cases
- Mês anterior `=0`: variação não é calculada (evita divisão por zero), exibe "—" no badge.
- Despesas pendentes em status `draft`: incluem ou não? **Decisão:** incluir (queremos saber gasto realizado, independente do estágio do relatório). Documentar no `<CardDescription>` como tooltip se possível.
- Datas no fuso BRT: usar `date` (DATE type, sem timezone) — já é o caso na coluna `expenses.date`.
