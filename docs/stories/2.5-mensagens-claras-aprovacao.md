# Story 2.5: Mensagens claras de erro/sucesso na decisão de aprovação

## Status: Approved

## Description

Como **gestor**, quero feedback claro quando minha decisão é confirmada (ou falha), **para** ter certeza do que aconteceu sem precisar recarregar a página.

> **Contexto:** o `ApprovalQueue.tsx` atual NÃO trata `error` retornado pelo `useReports({status: 'submitted'})` — só `isLoading` e empty state. O `useApproveReportRpc` em `useReportActions.ts` exibe toast genérico em sucesso ("Relatório aprovado!") e erro genérico ("Erro ao processar: ..."). Falta: (a) tratamento de erro state na fila, (b) toasts mais informativos com nome do relatório, (c) anti dupla submissão.

## Acceptance Criteria

- [ ] **Given** o `useReports` retorna erro (rede, RLS, etc.), **when** o `ApprovalQueue` renderiza, **then** exibe um bloco de erro com `<AlertTriangle>` + texto "Não foi possível carregar a fila" + botão "Tentar novamente" — não tela em branco nem skeleton infinito.
- [ ] **Given** aprovo um relatório com sucesso, **when** o RPC retorna OK, **then** o toast mostra: `"Relatório [título] aprovado"` (não genérico). Mesmo padrão para reprovação.
- [ ] **Given** o RPC `admin_decide_report` falha (e.g., relatório já decidido por outro gestor em outra aba), **when** o erro retorna, **then** o toast mostra mensagem útil: `"Não foi possível processar: [motivo amigável]"`. Mensagens técnicas do Postgres (códigos PG) são traduzidas em pt-BR onde possível, com fallback para a mensagem original.
- [ ] **Given** clico em "Aprovar" no diálogo de confirmação, **when** o request está em-flight, **then** o botão fica `disabled` (já implementado parcialmente — confirmar `approveReport.isPending`); duplo clique não dispara segunda chamada.
- [ ] **Given** ocorreu falha em uma aprovação anterior, **when** clico novamente em "Tentar novamente" (dentro do diálogo ou na fila), **then** o estado de erro é resetado e a operação re-executa.
- [ ] **Given** o toast aparece em mobile (390x844), **when** o teclado virtual está aberto, **then** o toast continua visível em `top-center` (já garantido pela Story 1.4 — confirmar que herdou).
- [ ] **Given** o toast aparece, **when** swipe pra cima ou clique em X, **then** desaparece imediatamente.

### Tradução de erros do Postgres
- Criar utility `src/lib/db-errors.ts`:
  ```ts
  const ERROR_MAP: Record<string, string> = {
    '23505': 'Operação duplicada — esse registro já existe.',
    'P0001': '', // RAISE EXCEPTION custom — usar a mensagem original
  };
  export function translateDbError(err: unknown): string {
    const msg = (err as { message?: string })?.message || 'Erro desconhecido';
    // Casos custom RAISE no admin_decide_report já vêm em pt-BR ("Apenas gestores podem...").
    // Apenas filtrar prefixos genéricos como "Failed to fetch" para algo amigável.
    if (msg.includes('Failed to fetch')) return 'Sem conexão. Verifique sua internet e tente novamente.';
    if (msg.includes('JWT')) return 'Sessão expirada. Faça login novamente.';
    return msg;
  }
  ```
- Usar em `onError`: `toast.error(translateDbError(error))`.
