# Story 2.6: Confirmação destrutiva ao rejeitar

## Status: Approved

## Description

Como **gestor**, quero confirmar minha intenção ao rejeitar um relatório (ação destrutiva e visível ao funcionário), **para** evitar tap acidental e garantir que o motivo seja substancial.

> **Contexto:** o diálogo atual em `ApprovalQueue.tsx:161-200` exige comentário não-vazio para rejeitar (`disabled={... || (decision === 'rejected' && !comment)}` linha 193). Mas aceita 1 caractere. Em mobile, dialog centralizado sobrepõe o trigger. Esta story endurece: comentário ≥10 caracteres, drawer mobile, label do botão muda dinamicamente.

## Acceptance Criteria

- [ ] **Given** sou gestor abrindo o diálogo "Reprovar relatório", **when** estou em mobile (390x844), **then** a UI é um **Drawer (bottom-sheet)** que sobe de baixo, ocupa altura natural do conteúdo + safe-area-inset-bottom — não mais Dialog centralizado.
- [ ] **Given** estou em desktop (≥1024px), **when** abro a mesma ação, **then** continua sendo **Dialog centralizado** (comportamento atual preservado).
- [ ] **Given** o textarea está vazio, **when** vejo o botão "Reprovar", **then** está **disabled** com texto "Reprovar". Mensagem auxiliar: "Informe o motivo (mín. 10 caracteres)".
- [ ] **Given** digito 5 caracteres no textarea, **when** o `onChange` dispara, **then** o botão **continua disabled**; mensagem auxiliar mostra contador "5/10 caracteres".
- [ ] **Given** atinjo 10+ caracteres válidos (não-só-espaços via `.trim()`), **when** o estado atualiza, **then** o botão **habilita** e o label muda para **"Confirmar Rejeição"** (reforço visual).
- [ ] **Given** confirmo, **when** o request está em-flight, **then** o botão fica disabled com `<Loader2 className="animate-spin">` à esquerda do texto.
- [ ] **Given** o drawer mobile está aberto, **when** swipe pra baixo OU toco fora dele, **then** o drawer fecha **sem submeter** (comportamento padrão `<Drawer>` shadcn).
- [ ] **Given** o drawer mobile está aberto, **when** o teclado virtual abre ao focar no textarea, **then** o drawer ajusta scroll para que o textarea + botão sejam visíveis (comportamento esperado do shadcn `<Drawer>`).

## Technical Notes

### Wrapper condicional Dialog/Drawer
- **Arquivo:** `src/components/reports/ApprovalQueue.tsx`
- O `<Dialog>` atual (linhas 161-200) será substituído por wrapper condicional:
  ```tsx
  const isMobile = useIsMobile(); // já importado linha 29
  const Container = isMobile ? Drawer : Dialog;
  const ContainerContent = isMobile ? DrawerContent : DialogContent;
  // ... e demais subcomponentes
  ```
- shadcn já tem `<Drawer>` em `src/components/ui/drawer.tsx` (vem do template Lovable; confirmar com `ls src/components/ui/`). Se faltar, adicionar via `npx shadcn add drawer`.

### Validação de comprimento
- Estado já existe: `const [comment, setComment] = useState('')` (linha 40).
- Calcular `const trimmedLength = comment.trim().length;` no render.
- Botão `disabled={approveReport.isPending || (decision === 'rejected' && trimmedLength < 10)}`.
- Mensagem auxiliar abaixo do textarea:
  ```tsx
  {decision === 'rejected' && (
    <p className={cn("text-xs", trimmedLength < 10 ? "text-destructive" : "text-muted-foreground")}>
      {trimmedLength < 10
        ? `Mínimo 10 caracteres para reprovar (${trimmedLength}/10)`
        : `${trimmedLength} caracteres`}
    </p>
  )}
  ```

### Label dinâmico do botão
- Substituir o texto fixo:
  ```tsx
  {approveReport.isPending && <Loader2 className="mr-2 h-4 w-4 animate-spin" />}
  {decision === 'approved'
    ? 'Aprovar'
    : trimmedLength >= 10 ? 'Confirmar Rejeição' : 'Reprovar'}
  ```

### Aplicar mesmo padrão em `ReportDetail.tsx`
- O `ReportDetail.tsx` também tem dialog de rejeição (linhas 110-115). Aplicar **MESMO wrapper condicional** + validação ≥10 + label dinâmico para consistência.
- Atenção: `ReportDetail.tsx` já tem rejeição **de despesa individual** (Story 2.3). Esta story 2.6 cuida só da rejeição **do relatório inteiro** — não duplicar lógica entre as duas.
