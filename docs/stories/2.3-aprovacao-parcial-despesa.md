# Story 2.3: Aprovação parcial — rejeitar despesa individual com comentário

## Status: Approved

## Description

Como **gestor**, quero rejeitar despesas individuais dentro de um relatório (não só o relatório inteiro), **para** que o funcionário ajuste apenas o que está errado em vez de refazer tudo.

> **Contexto:** a tabela `expense_reviews` já existe (migration `20260223161405_*`). O hook `useReviewExpense` também. `ReportDetail.tsx:74-97` já tem `handleApproveExpense` e `handleRejectExpense`. Esta story é principalmente **polish + UX mobile + edge case** ao redor de funcionalidade que existe parcialmente.

## Acceptance Criteria

- [ ] **Given** sou gestor revisando um relatório submitted, **when** vejo cada despesa, **then** existem 2 ações: "Aprovar despesa" e "Rejeitar despesa".
- [ ] **Given** clico "Rejeitar despesa", **when** o diálogo/drawer abre, **then** preciso preencher um comentário **com mínimo de 10 caracteres** para o botão de confirmar habilitar.
- [ ] **Given** confirmei a rejeição individual, **when** a página recarrega, **then** a despesa exibe badge "Reprovada" (vermelho) com o comentário visível inline ou em tooltip; despesas não-revisadas exibem cinza/neutro; aprovadas verde.
- [ ] **Given** rejeitei N despesas individualmente, **when** vou aprovar o relatório inteiro como "approved", **then** a UI alerta "X despesa(s) ainda rejeitada(s) — confirmar mesmo assim?" antes de prosseguir.
- [ ] **Given** confirmei a aprovação do relatório com despesas individualmente rejeitadas, **when** o backend processa, **then** o status das despesas individualmente rejeitadas é **mantido como rejected** (não é sobrescrito para `approved` pelo `admin_decide_report`).
- [ ] **Given** estou em mobile (390x844), **when** clico em "Rejeitar" de uma despesa, **then** a UI usa **Drawer (bottom sheet)** em vez de Dialog centralizado — mais natural pro toque.
- [ ] **Given** as ações por despesa renderizam, **when** estou em mobile, **then** os botões têm altura ≥40px (`h-10` mínimo) e ficam legíveis sem zoom.

## Technical Notes

### RPC `admin_decide_report` — preservar rejeições individuais
- **Arquivo:** `supabase/migrations/<timestamp>_admin_decide_report_v3.sql` (novo)
- A RPC atual em `supabase/migrations/20260208191418_*` faz:
  ```sql
  UPDATE public.expenses e
  SET status = p_decision::expense_status, ...
  FROM public.report_items ri
  WHERE ri.report_id = p_report_id AND ri.expense_id = e.id;
  ```
- Modificar para EXCLUIR despesas que já têm `expense_reviews.decision = 'rejected'`:
  ```sql
  UPDATE public.expenses e
  SET status = p_decision::expense_status, updated_at = now()
  FROM public.report_items ri
  WHERE ri.report_id = p_report_id
    AND ri.expense_id = e.id
    AND NOT EXISTS (
      SELECT 1 FROM public.expense_reviews er
      WHERE er.expense_id = e.id
        AND er.report_id = p_report_id
        AND er.decision = 'rejected'
    );
  ```
- E para as rejeitadas individualmente, manter status `rejected` independente da decisão do relatório:
  ```sql
  UPDATE public.expenses e
  SET status = 'rejected'::expense_status, updated_at = now()
  FROM public.report_items ri, public.expense_reviews er
  WHERE ri.report_id = p_report_id
    AND ri.expense_id = e.id
    AND er.expense_id = e.id
    AND er.report_id = p_report_id
    AND er.decision = 'rejected';
  ```
- **Migration aditiva:** `CREATE OR REPLACE FUNCTION` (não DROP).

## Testing Requirements

### Manual
- Criar relatório com 3 despesas, submeter
- Como gestor: rejeitar 1 despesa com comentário "ok" (8 chars) → botão deve estar disabled
- Trocar para "comentário válido" (≥10 chars) → habilita
- Aprovar 1 outra despesa (verde)
- Tentar aprovar o relatório inteiro: confirmação extra "1 despesa rejeitada — confirmar?"
- Confirmar: status do relatório vira `approved`, mas a despesa rejeitada continua `rejected` no banco e na UI

### Smoke mobile
- Drawer (bottom sheet) abre ao clicar "Rejeitar despesa"; comentário cabe; botão "Confirmar" tem ≥44px
- Não há "vazamento" do drawer (não ocupa toda a tela em viewport pequeno)

### Edge cases
- Rejeitar despesa, depois mudar de ideia e aprovar a mesma → aprovação sobrescreve rejeição? (Validar com QA — se necessário, adicionar lógica de "limpar review anterior")
- Comentário com 10 espaços (sem texto útil) → após `.trim()`, conta como 0 → botão disabled. ✓
- 5+ despesas rejeitadas → contagem correta no warning
