# Story 1.1: Configurar `OPENAI_API_KEY` na edge function

## Status: Approved

## Description

Como **admin**, quero que o OCR de comprovantes funcione em produção, **para que** os comprovantes sejam validados automaticamente e o usuário tenha confiança nos dados extraídos.

> **Contexto:** a edge function `validate-receipt` já está implementada e usa OpenAI Vision (GPT-4o-mini) com tool-calling. Hoje, se a chave não estiver presente, a função retorna **HTTP 500** com erro genérico — o usuário recebe um erro confuso e não sabe diferenciar "OCR fora do ar" de "comprovante inválido".

## Acceptance Criteria

- [ ] **Given** o admin tem acesso ao painel do projeto Supabase, **when** ele configura `OPENAI_API_KEY` nos Edge Function secrets, **then** a chave fica disponível em `Deno.env.get("OPENAI_API_KEY")` na função `validate-receipt`.
- [ ] **Given** a função está deployada com a chave configurada, **when** o frontend faz upload de uma foto de comprovante real (JPEG ou PNG), **then** a resposta retorna `{ extracted_date, extracted_amount_cents, confidence }` válidos (não null para uma nota legível).
- [ ] **Given** a chave NÃO está configurada, **when** o frontend chama a função, **then** a resposta é HTTP **503** (Service Unavailable, não mais 500) com body `{ error: "OCR temporariamente indisponível", code: "OCR_UNAVAILABLE" }`.
- [ ] **Given** a função retorna 503, **when** o frontend recebe o erro, **then** o usuário vê um toast: "OCR indisponível no momento. Preencha os dados manualmente." (não a mensagem técnica).
- [ ] **Given** o OCR falha, **when** o usuário preenche os campos manualmente e clica salvar, **then** a despesa é salva normalmente — OCR não é pré-requisito para criar despesa.
- [ ] **Given mobile (390x844 viewport)**, **when** o toast de erro aparece, **then** ele é legível, posicionado em `top` (não coberto por teclado virtual) e some por swipe ou após 5s.

## Technical Notes

### Parte DevOps (Story 1.1a)
- Acessar Supabase Dashboard → Project → Edge Functions → Secrets.
- Adicionar secret `OPENAI_API_KEY` com a chave do plano OpenAI da empresa.
- Validar com `curl` direto contra a função (passos no campo "Testing Requirements" abaixo).
- Garantir que `RESEND_API_KEY` (Story 1.3) seja adicionada na mesma sessão para evitar reabrir o painel depois.

### Parte de código (Story 1.1b)
- **Arquivo:** `supabase/functions/validate-receipt/index.ts`
- **Linhas 15-21:** mudar status `500` → `503`, atualizar body para `{ error: "OCR temporariamente indisponível", code: "OCR_UNAVAILABLE" }`. Manter a checagem `if (!OPENAI_API_KEY)` no início.
- **Arquivo:** `src/hooks/useValidateReceipt.ts`
- Verificar se já trata `response.status === 503` ou `error.code === "OCR_UNAVAILABLE"` distintamente. Se não, adicionar branch que dispara toast amigável e marca o resultado como `status: "unavailable"` (não `error`), permitindo o usuário continuar manualmente.
- **Arquivo:** `src/components/expenses/ReceiptValidation.tsx`
- Garantir que quando `status === "unavailable"`, exibe mensagem "OCR indisponível, preencha manualmente" em vez de erro genérico.

## Testing Requirements

### Teste manual (pré-deploy)
1. Sem a chave configurada, chamar a edge function:
   ```bash
   curl -i -X POST <SUPABASE_URL>/functions/v1/validate-receipt \
     -H "Authorization: Bearer <SUPABASE_ANON_KEY>" \
     -H "Content-Type: application/json" \
     -d '{"image_base64":"abc","mime_type":"image/jpeg"}'
   ```
   → esperar HTTP 503 com `{ "error": "OCR temporariamente indisponível", "code": "OCR_UNAVAILABLE" }`.
2. Com a chave configurada, repetir com `image_base64` real (foto pequena de cupom fiscal) e validar `extracted_date`, `extracted_amount_cents`, `confidence`.

### Smoke mobile (Chrome DevTools 390x844)
- Forçar erro 503 (remover key temporariamente em ambiente staging) e validar UX no fluxo "Nova despesa → tirar foto → erro → salvar manualmente".

### Edge cases
- HEIC convertido (já é tratado via `heic2any` no frontend antes de chamar a função).
- Imagem corrompida → função retorna `confidence: low` com `extracted_*: null` (já implementado, manter).
- Rate limit OpenAI 429 → frontend deve tratar com retry manual ou mensagem específica (já existe em linhas 120-125).
