# Story 2.2: Fila destaca relatórios com despesas fora da política

## Status: Approved

## Description

Como **gestor**, quero ver de relance se um relatório na fila contém despesas fora da política, **para** priorizar a revisão e dar atenção redobrada antes de aprovar.

> **Contexto:** o schema já tem `expenses.is_out_of_policy` (boolean default false). A fila atual não destaca isso — gestor precisa abrir cada relatório para descobrir. Risco real de aprovar sem perceber.

## Acceptance Criteria

- [ ] **Given** sou gestor com relatórios na fila, **when** abro `/app/reports?status=submitted` (ou tab Aprovação), **then** cada relatório com `expense_count_out_of_policy > 0` exibe um badge âmbar "⚠️ X fora da política".
- [ ] **Given** o badge está visível, **when** clico nele, **then** sou levado para `/app/reports/:id` com a UI rolada/destacada para as despesas fora da política (filtro pré-aplicado se houver, ou pelo menos rolagem para a primeira).
- [ ] **Given** o relatório tem zero despesas fora da política, **when** ele aparece na fila, **then** **NÃO** aparece o badge (sem ruído visual).
- [ ] **Given** estou em mobile (390x844), **when** o badge aparece em um card cuja linha do título já está cheia, **then** o badge **quebra para a próxima linha** (não corta o título).
- [ ] **Given** estou em desktop, **when** o badge aparece na tabela, **then** ele fica próximo ao título do relatório (mesma célula ou imediatamente ao lado), não em coluna separada (evita custo de layout).

## Technical Notes

### Hook `useReports`
- **Arquivo:** `src/hooks/useReports.ts`
- A query atual provavelmente faz `select('*, expense_count, total_cents...')`. Adicionar agregação para `expense_count_out_of_policy`.
- **Opção A — sub-query SQL via `select` do Supabase JS:**
  ```ts
  .select(`
    *,
    items:report_items(
      expense:expenses(is_out_of_policy)
    )
  `)
  ```
  E calcular `expense_count_out_of_policy` no client (`items.filter(i => i.expense?.is_out_of_policy).length`).
- **Opção B — view/RPC server-side** (mais limpo se o volume crescer): criar view `reports_with_counts` ou RPC `get_reports_with_oop_count(...)`. **Para o MVP, Opção A é suficiente.**
- Adicionar `expense_count_out_of_policy: number` à interface do hook (se houver). Se não existir interface centralizada, expor via `(report as Report & { expense_count_out_of_policy?: number }).expense_count_out_of_policy`.

### UI no `ApprovalQueue`
- **Arquivo:** `src/components/reports/ApprovalQueue.tsx`
- **Bloco mobile (cards, ~linha 100):** após `report.user?.full_name`, adicionar:
  ```tsx
  {report.expense_count_out_of_policy > 0 && (
    <Badge
      variant="outline"
      className="mt-2 border-amber-500 bg-amber-50 text-amber-700 dark:bg-amber-950/40 dark:text-amber-400 cursor-pointer"
      onClick={(e) => { e.stopPropagation(); navigate(`/app/reports/${report.id}#out-of-policy`); }}
    >
      <AlertTriangle className="mr-1 h-3 w-3" />
      {report.expense_count_out_of_policy} fora da política
    </Badge>
  )}
  ```
- **Bloco desktop (tabela, ~linha 222):** dentro da célula do título, ao lado da badge "Atrasado":
  ```tsx
  {report.expense_count_out_of_policy > 0 && (
    <Badge variant="outline" className="text-xs border-amber-500 bg-amber-50 text-amber-700">...</Badge>
  )}
  ```
- Reutilizar o mesmo componente de Badge para evitar duplicação visual.

### Deep-link em `ReportDetail`
- **Arquivo:** `src/pages/app/ReportDetail.tsx`
- Detectar hash `#out-of-policy` no `useLocation`; se presente, fazer scroll para a primeira despesa com `is_out_of_policy=true` ou aplicar filtro UI (a definir conforme a tela atual). MVP aceita scroll simples via `document.querySelector('[data-out-of-policy="true"]')?.scrollIntoView({behavior: 'smooth'})`.
- Adicionar atributo `data-out-of-policy={item.expense.is_out_of_policy}` na linha/card de despesa em `ReportDetail`.
